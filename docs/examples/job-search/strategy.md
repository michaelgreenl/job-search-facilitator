# Job Search Strategy

## Outcome

Return each active role that independently passes `post-evaluation.md`. Candidate count must not change a verdict.

Search responsibilities before exact titles. Use the target role order from `user-info.md`.

## History

Exclude every identity already stored in the application. This includes unlabeled and unapplied roles.

Collapse duplicates by employer requisition, stable ATS identity, and canonical URL.

Do not use old reports, labels, or application outcomes to judge current fit.

## Discovery scope

Search for roles whose main work overlaps the target responsibilities in `user-info.md`.

Promote every active and legitimate role with one substantial target responsibility. Apply objective rejection rules before promotion.

Do not reject a role only for one bounded framework, language, or domain transfer. Final judgment owns that decision.

## Ranking

Rank selected roles with this order:

1. Direct evidence for the central responsibilities.
2. Realistic level and required experience.
3. Strength of a truthful application case.
4. The role-family order in `user-info.md`.
5. Location, compensation, and application effort.
6. Freshness, legitimacy, and application-path quality.

Rank `target` roles before `quick-app` roles unless the practical opportunity is clearly stronger.
